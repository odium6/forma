# FORMA

Персональное local-first PWA-приложение для контроля веса, параметров тела, привычек и долгосрочного прогресса.
Работает без регистрации, сервера и интернета (после первой загрузки). Все данные — включая фото — хранятся в IndexedDB на устройстве.

## Быстрый старт

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # unit/интеграционные тесты (Vitest)
npm run build        # проверка типов + production-сборка в dist/
npm run preview      # http://localhost:4173 — сборка с Service Worker
npm run e2e          # E2E (Playwright) против production-сборки
```

Требования: Node.js 20.19+ (проверено на 24). E2E по умолчанию запускаются в установленном Microsoft Edge
(`PW_CHANNEL=msedge`). Для Chrome — `PW_CHANNEL=chrome`, для встроенного Chromium — `npx playwright install chromium` и `PW_CHANNEL=`.
`npm run icons` пересобирает PNG-иконки и splash-экраны iOS из `public/icon.svg` (нужен Edge или Chrome).

## Бесплатное развёртывание

Сборка — полностью статическая (`dist/`), пути относительные (`base: './'`), маршрутизация через hash — работает в любой подпапке.

- **GitHub Pages** — готовый workflow `.github/workflows/deploy-pages.yml`: включите *Settings → Pages → Source: GitHub Actions* и сделайте push в `main`.
- **Cloudflare Pages** (Free, без карты): Build command `npm run build`, output `dist`. Файл `public/_headers` добавляет заголовки безопасности.
- **Netlify** (Free): то же самое; `_headers` поддерживается.

HTTPS обязателен для Service Worker, установки PWA, уведомлений и биометрии (localhost — исключение).
Установка на iPhone: Safari → «Поделиться» → «На экран „Домой“».

## Архитектура

```
src/
  domain/types.ts        модель данных (единая для хранилища, бэкапа и логики)
  db/db.ts               схема IndexedDB (версионируемая), отдельные хранилища для метаданных и бинарных фото
  state/store.ts         снимок данных в памяти + мутации (сначала запись в IDB, затем обновление UI)
  lib/math/              series (сглаживание, тренды), forecast, goals (безопасность целей), progress, body
  lib/                   habits, achievements, insights, reminders, reports, summary, security, images, backup/, export/
  ui/                    дизайн-система: Sheet (<dialog>), контролы, LineChart, иконки, логотип
  app/                   оболочка: Layout, тема, блокировка, PWA
  features/              экраны: home, progress, habits, calendar, photos, achievements, reports, settings, onboarding
  sw.ts                  Service Worker: precache оболочки, действия уведомлений
```

Вся математика и бизнес-логика — чистые функции в `src/lib`, без React; UI их только вызывает.

## Алгоритмы

- **Дневной ряд** — несколько взвешиваний за день усредняются; пропущенные дни не интерполируются.
- **Скользящее среднее 7 дней** — по календарному окну, значение только при ≥ 3 измерениях в окне.
- **Тренд** — экспоненциальное сглаживание с учётом пропусков: `α_eff = 1 − (1 − 0,1)^Δдней`.
- **Темп (14/30/90 дней)** — МНК с одним проходом отсечения выбросов (> 3σ по MAD). Нужны минимум точки и охват по дням, иначе «мало данных».
- **Прогноз** — регрессия за 28 дней (≥ 6 измерений, охват ≥ 10 дней). Диапазон дат: `темп ± (1,28·SE + 20% темпа)`. Статусы: недостаточно данных, достигнута, плато, тренд от цели, дальше 3 лет — без даты.
- **Прогресс** — `(тренд − старт) / (цель − старт)`, ограничен [0; 1]; отдельно показываются «вес дальше от цели, чем на старте» и «цель превышена». Новая цель стартует от текущего тренда, история не меняется.
- **Безопасность целей** — взрослые: цель ниже ИМТ 18,5 блокируется; темп > 1%/нед (похудение) или > 0,5%/нед (набор) — «небезопасно» с предложением срока. До 18 лет взрослые нормы ИМТ не применяются, персональный план похудения не строится (до 14 лет цель снижения веса блокируется).
- **Энергия** — Mifflin–St Jeor × коэффициент активности, только для взрослых, с нижним порогом 1200/1500 ккал. % жира по обхватам — метод ВМС США.
- **Серии привычек** — один пропуск прощается, если не подряд и не чаще раза в 7 периодов; «N раз в неделю» считается неделями; расписания версионируются, рекорд никогда не уменьшается.
- **Достижения** — вычисляются из данных и датируются днём события; полученные не отзываются.

## Хранение, приватность, безопасность

- IndexedDB, запрос `navigator.storage.persist()`, напоминания о резервной копии.
- Фото: оригинал не изменяется, проверка по сигнатуре и реальному декодированию, отдельная миниатюра 480 px; загрузка по видимости, object URL освобождаются.
- PIN: PBKDF2-SHA-256, 310 000 итераций, соль, сравнение за постоянное время, прогрессивная задержка после 5 ошибок. Биометрия — WebAuthn platform authenticator с проверкой флага UV. **Это блокировка интерфейса, а не шифрование хранилища** — приложение говорит об этом прямо.
- Резервная копия: JSON с SHA-256 по каноническому JSON; импорт проходит строгую Zod-схему (диапазоны, длины, форматы, ссылочная целостность) до записи; запись — одной транзакцией; PIN и привязка биометрии не экспортируются.
- CSV защищён от формул-инъекций. В production действует строгая CSP. Нет аналитики, трекеров и внешних запросов.

## Уведомления: что реально возможно

Сервера нет, поэтому Web Push (доставка при закрытом приложении) не используется. Напоминания показываются через `ServiceWorkerRegistration.showNotification`, пока FORMA открыта или её вкладка жива; пропущенное за последние 3 часа покажется один раз при открытии. Каждое срабатывание фиксируется в IndexedDB — повторов нет; «Отложить» ограничено 3 разами. Действия «Внести данные / Отложить / Пропустить сегодня» поддерживаются там, где браузер поддерживает actions (Chrome/Edge; iOS их не показывает). На iOS уведомления доступны только в установленной PWA (iOS 16.4+). Для гарантированной доставки есть экспорт расписания в `.ics` (включая чередование чётных/нечётных недель).

## Ограничения

- Облачной синхронизации нет (осознанно): бесплатные варианты требуют сервера с аутентификацией; перенос данных — через резервную копию.
- Liquid Glass с преломлением Glisse включает только в Chromium; в Safari/WebKit автоматически используется матовое стекло (blur), а в режиме «Liquid Glass выкл.» — непрозрачные поверхности.
- E2E выполнены в Chromium (Edge). Поведение в реальном Safari на iPhone и в установленной PWA на iOS вручную не проверялось в этой среде.
- HEIC не поддерживается напрямую (iOS обычно отдаёт JPEG при выборе из «Фото»).
